* PostgreSQL
* users + employees

* login real
* portal de clientes

No quiero romper nada del sistema actual.

Quiero avanzar a la siguiente fase: **Alias de clientes y puestos**.

Objetivo:
permitir que guardias, custodios, supervisores y operadores puedan referirse a clientes, puestos, rutas y servicios usando alias operativos o nombres comunes, sin necesidad de escribir el nombre legal exacto.

Ejemplos esperados:

* "gallo"
* "custodio gallo"
* "salvavidas"
* "ruta gallo"
* "tienda dolores"

El sistema debe poder mapear esos términos a:

* cliente legal correcto
* puesto/ruta/servicio correcto
* ubicación cuando aplique

Haz esto:

## 1. Base de datos

Crea o amplía la estructura necesaria para soportar alias.

* ubicacion
* estado
* createdAt
* updatedAt

### Tabla position_aliases

Campos sugeridos:

* id
* positionId
* alias
* aliasType
* isActive
* createdAt
* updatedAt

## 2. Resolver alias

Crea una utilidad o servicio reusable para resolver alias a partir de texto libre.

Entrada:

* string con texto libre

Salida:

* cliente encontrado
* puesto/ruta encontrado
* coincidencias múltiples si aplica

Debe soportar:

* coincidencia exacta
* coincidencia parcial básica
* respuesta con múltiples resultados si hay ambigüedad

## 3. Endpoints/API

Crea endpoints para:

* listar alias de clientes
* crear alias de clientes
* editar alias de clientes
* listar puestos/rutas
* crear alias de puestos/rutas
* probar resolución de alias

## 4. Admin UI

* ver clientes con sus alias
* crear alias

* crear alias para puestos/rutas
* probar un texto y ver cómo lo resolvería el sistema
