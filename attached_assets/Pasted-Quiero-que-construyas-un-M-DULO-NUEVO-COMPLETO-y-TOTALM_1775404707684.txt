4. CASO DE USO PRINCIPAL DEL AGENTE
======================================================================

Quiero soportar este flujo:

1. Cada agente tiene un llavero NFC personal.
2. Cada llavero NFC está asociado a un empleado de prueba o a un empleado real SOLO EN MODO REFERENCIAL.
3. Cada puesto tiene un teléfono o tablet asignado.
4. El dispositivo del puesto está registrado como dispositivo autorizado.
5. El agente llega al puesto.
6. Acerca su llavero NFC al dispositivo del puesto.
7. El sistema reconoce el NFC.
8. El sistema identifica al agente.
9. El sistema toma una foto.
10. El sistema abre una pantalla de inicio de turno.
11. El sistema registra un evento piloto de marcaje.
12. El sistema compara contra una programación de prueba o contra lectura de turnos en modo solo lectura.
13. El sistema clasifica el evento como:
   - inicio correcto
   - fuera de programación
   - cobertura posible
   - validación pendiente
   - intento sospechoso

IMPORTANTE
Aunque el llavero identifica al agente, el NFC por sí solo NO debe confirmar asistencia real.
Solo debe iniciar el flujo de validación.

======================================================================
5. CASO DE USO PRINCIPAL DEL SUPERVISOR
======================================================================

Quiero soportar este flujo:

1. Cada supervisor tiene su propia ficha o llavero NFC.
2. Cuando el supervisor acerca su NFC al dispositivo del puesto:
   - NO se abre el flujo de agente
   - se abre el modo supervisor
3. El modo supervisor debe abrir un formulario operativo del puesto.

El formulario de supervisor debe permitir como mínimo:

A. Estado del arma
- asignada
- sin novedad
- dañada
- mantenimiento
- no entregada

B. Estado del uniforme del agente
- completo
- incompleto
- dañado
- requiere reemplazo

C. Estado del equipo
- radio
- bastón
- linterna
- chaleco
- munición
- libreta
- otros configurables

Cada ítem puede estar:
- OK
- faltante
- dañado
- reemplazar

D. Estado del puesto
- sin novedad
- con novedad
- riesgo detectado
- observación del cliente

E. Estado del agente
- presente
- no presente
- uniforme incompleto
- sin arma
- observación disciplinaria
- requiere seguimiento RRHH

F. Observaciones
- campo de texto libre
- opción de adjuntar foto si es posible

Todo esto debe quedar registrado como inspección operativa piloto.

======================================================================
6. SEGURIDAD DEL MÓDULO
======================================================================

Este punto es crítico.

Quiero que el módulo esté diseñado para evitar fraude básico. Por lo tanto:

1. El NFC del agente NO debe ser suficiente para marcar desde cualquier dispositivo.
2. Solo dispositivos autorizados deben poder registrar eventos válidos.
3. Cada dispositivo debe estar amarrado a un puesto de prueba.
4. Si un NFC se usa desde un dispositivo no autorizado, el sistema debe rechazar el intento.
5. Si un NFC se usa fuera de la ventana horaria esperada, el sistema debe marcarlo como irregular.
6. La foto debe quedar almacenada como evidencia del evento piloto.
7. Si el reconocimiento facial aún no se implementa, por ahora solo guardar la foto y el estado de validación como:
   - validado manualmente
   - pendiente de revisión
   - rechazado
8. Dejar preparada la arquitectura para una futura validación facial, pero NO hacer obligatoria la integración si eso complica esta fase.

IMPORTANTE
No quiero que por ahora se implemente una dependencia compleja que ponga en riesgo el módulo.
Prefiero:
- NFC
- dispositivo autorizado
- foto
- trazabilidad
y dejar reconocimiento facial avanzado para después.
