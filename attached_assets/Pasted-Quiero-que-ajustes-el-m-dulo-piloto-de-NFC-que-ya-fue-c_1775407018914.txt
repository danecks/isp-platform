======================================================================
1. CAMBIO FUNCIONAL REQUERIDO
======================================================================

Quiero que el sistema ya no intente usar ni asumir:
- serial del teléfono
- IMEI
- identificadores físicos del hardware
- ningún dato del dispositivo que dependa del navegador o permisos especiales del sistema operativo

En cambio, quiero que cada dispositivo del puesto funcione con estas identidades:

1. `device_code`
   - identificador visible y administrativo
   - ejemplo: GARITA-NORTE-01
   - lo usa RRHH / operaciones para reconocer el equipo

2. `device_name`
   - nombre editable y humano
   - ejemplo: Tablet Garita Norte

3. `device_uuid`
   - identificador interno único generado por el sistema
   - no editable
   - no depende del hardware real
   - se genera al enrolar el dispositivo

4. `device_token`
   - secreto de autenticación del kiosco
   - usado para validar que ese navegador/dispositivo está autorizado
   - debe renovarse o invalidarse si el dispositivo se revoca

Quiero que el backend reconozca el dispositivo por:
- `device_uuid`
- `device_token`

y no por el serial físico del teléfono.

======================================================================
2. PRINCIPIO DE SEGURIDAD
======================================================================

El sistema debe asumir que:
- cualquier persona puede tener un teléfono con NFC
- un agente podría leer su llavero desde otro teléfono
- leer el NFC NO es suficiente para marcar

Por lo tanto, un marcaje piloto solo debe considerarse válido si:
1. el tag NFC existe y está activo
2. el dispositivo está enrolado
3. el `device_uuid` está registrado
4. el `device_token` coincide
5. el dispositivo está activo
6. el dispositivo está asignado al puesto correcto
7. el evento cumple las reglas del sandbox

Si no, debe rechazarse como:
- dispositivo no autorizado
- token inválido
- dispositivo revocado
- puesto incorrecto
- intento irregular

5. FLUJO DE ENROLAMIENTO DEL DISPOSITIVO
======================================================================

Quiero crear un flujo claro de enrolamiento del kiosco.

CASO 1: primer enrolamiento
1. un admin crea el dispositivo en el panel
2. el sistema genera:
   - `device_code`
   - `device_uuid`
   - `device_token`
3. el dispositivo queda en estado:
   - pendiente de enrolamiento
   o
   - listo para activar
4. desde la pantalla kiosco se introduce o escanea un código de activación
5. el kiosco guarda localmente:
   - `device_uuid`
   - `device_token`
6. el backend marca el dispositivo como enrolado

CASO 2: re-enrolamiento
Si el navegador pierde datos o se cambia de equipo:
- debe poder revocarse el enrolamiento anterior
- debe generarse nuevo token
- debe re-enrolarse el kiosco sin romper historial
