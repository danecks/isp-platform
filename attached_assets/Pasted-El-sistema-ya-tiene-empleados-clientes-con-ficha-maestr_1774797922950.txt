El sistema ya tiene:
	•	empleados
	•	clientes con ficha maestra
	•	sedes operativas
	•	puestos operativos
	•	zonas operativas globales
	•	supervisores asignados por zona
	•	pizarrón operativo
	•	cobertura diaria
	•	cierre operativo
	•	RRHH
	•	anticipos
	•	pre-planilla
	•	modelo de turnos en construcción o preparado

No quiero romper nada de lo existente.

Quiero corregir y normalizar la ficha del colaborador para que use correctamente el modelo operativo central y deje de depender de campos manuales que deberían venir derivados de la asignación.

Objetivo

Separar correctamente:
	1.	datos propios del colaborador
	2.	asignación operativa base
	3.	estado operativo actual

Y evitar inconsistencias como:
	•	supervisor escrito manualmente
	•	sede escrita manualmente
	•	cliente puesto manualmente
cuando todo eso debería venir de la asignación operativa y de la zona.

⸻

1. Qué debe quedarse como dato propio del colaborador

En la ficha del colaborador, mantener como datos editables propios:

Datos personales / laborales
	•	nombre
	•	DPI
	•	teléfonos
	•	área o departamento si aplica a nivel interno
	•	estado laboral
	•	sueldo_base
	•	horas_contrato
	•	tipo_jornada
	•	dia_descanso
	•	notas

Estos sí pueden editarse desde la ficha del colaborador.

⸻

2. Qué NO debe capturarse manualmente en la ficha

Quiero eliminar o dejar como solo lectura los campos que no deberían llenarse manualmente ahí, por ejemplo:
	•	supervisor
	•	sede
	•	cliente titular
	•	puesto titular
	•	zona operativa

Estos deben venir derivados desde una asignación operativa base, no capturarse dos veces.

⸻

3. Crear o reforzar asignación operativa base

Necesito una estructura clara y normalizada para la asignación operativa base del colaborador.

Si no existe una tabla formal, crear algo como:

employee_operational_assignments

Campos sugeridos:
	•	id
	•	employeeId
	•	clientId nullable
	•	sedeId nullable
	•	puestoId nullable
	•	operationalZoneId nullable
	•	turnoId nullable
	•	tipoAsignacion (titular, disponible, pool_relevo, sin_asignacion)
	•	activa
	•	createdAt
	•	updatedAt

Muy importante:
esta estructura debe ser la fuente oficial de:
	•	cliente titular
	•	sede titular
	•	puesto titular
	•	zona operativa
	•	supervisor derivado
	•	turno base

⸻

4. Supervisor derivado por zona

No quiero que el supervisor se seleccione manualmente en la ficha del colaborador.

Quiero que:
	•	si el colaborador tiene un puesto asignado en una zona operativa
	•	el sistema derive automáticamente el supervisor desde esa zona

Ejemplo:
puesto → zona operativa → supervisor de zona

Mostrar este supervisor en la ficha del colaborador como información derivada / solo lectura.

⸻

5. Soporte para colaboradores disponibles

Necesito que el sistema soporte colaboradores que:
	•	están contratados
	•	pero no tienen cliente fijo
	•	o están disponibles para relevos

Agregar y soportar estados de asignación operativa como:
	•	titular
	•	disponible
	•	pool_relevo
	•	sin_asignacion

Quiero que estos colaboradores puedan existir sin cliente titular obligatorio, pero que sí aparezcan correctamente en operación y en el pool cuando corresponda.

⸻

6. Turno base vinculado a la asignación

Quiero que el turno base del colaborador también venga de la asignación operativa base, no como texto suelto.

Si ya existe o se está construyendo una tabla de turnos:
	•	usar turnoId
	•	mostrar el turno asignado en la ficha del colaborador

Ejemplos:
	•	12x12
	•	24x24
	•	24x48
	•	8 horas
